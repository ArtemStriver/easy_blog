# FastAPI Blog Backend - тестовое задание

> Лёгкий и безопасный backend-сервис для блога с поддержкой админских CRUD-операций, 
> публичного API, JWT-аутентификации и системой ролей пользователей.

---

## Описание проекта

**FastAPI Blog Backend** — это REST API-сервис для управления блогом.  
Он реализует систему аутентификации с JWT (access + refresh токены), 
разграничение прав доступа (пользователь / администратор), 
CRUD-операции для постов и категорий, а также встроенную защиту от XSS через HTML-санитизацию.

---

## Используемые технологии

- Стек: Python 3.11+,  FastAPI, PostgreSQL, SQLAlchemy (async), Alembic
- Аутентификация: JWT (access + refresh)
- Хеширование паролей: bcrypt
- Санитизация HTML: bleach
- Тестирование: pytest
- Контейнеризация: Docker + Docker Compose 

---

## Запуск через Docker Compose

### 1. Клонируйте репозиторий

### 2. Создайте `.env` на основе `.env-example` (ничего не меняя в нем)

```bash
    cat .env-example > .env
```

### 3. Запустите сервисы:

```bash
    docker-compose up --build
```

### 4. После старта:
- API: http://localhost:8000
- OpenAPI / Swagger: http://localhost:8000/docs

---

## Локальный запуск (без Docker)

### 1. Клонируйте репозиторий себе на компьютер

### 2. Создайте `.env` на основе `.env-example`, при необходимости, внесите изменения для подключения к PostgreSQL

```bash
    cat .env-example > .env
```

### 3. Создайте виртуальное окружение и установи пакеты:

```bash
    python3 -m venv .venv 
```
```bash
    source .venv/bin/activate
```
```bash
    pip install -r requirements.txt
```

### 4. Настройте миграций (при необходимости):

```bash
    alembic init alembic
```
```bash
    alembic revision --autogenerate -m "new_migration"
```

### 5. Обнови миграции:

```bash
    alembic upgrade head
```

### 6. Запусти сервер:

```bash
    uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload 
```

### 7. После старта:
- API: http://localhost:8000
- OpenAPI / Swagger: http://localhost:8000/docs

## Пояснения:

В проекте был сделан ряд допущений, допустимых для тестового задания,
но нежелательных в production-версии:
- используется тип `Integer` вместо `UUID`, для повышения безопасности и уникальности записей при распределённом доступе рекомендуется использовать `UUID`;  
- упрощено взаимодействие с постами и категориями;  
- отсутствует подтверждение email, смена пароля и система восстановления аккаунта;  
- отсутствует автоматизированное тестирование (юнит и интеграционное);  
  вместо этого используется ручное тестирование — при запуске проекта в базу данных автоматически добавляются тестовые записи.
